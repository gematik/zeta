# Sicherheitsanforderungen an den Client-Hersteller

Die ZETA-Spezifikation definiert eine Reihe von Sicherheitsanforderungen — zum
einen direkt in der gemSpec_ZETA, zum anderen indirekt über referenzierte
Dokumente wie gemSpec_Krypt, OWASP Top 10 oder BSI TR-03161-1.

Nicht alle davon kann das ZETA-SDK erfüllen. Anforderungen an das sichere
Verteilen einer App etwa kann nur der Client-Hersteller umsetzen.

Die folgende Liste führt die Anforderungen auf, die das ZETA-SDK nicht abdeckt.
Sie sind damit Hinweise für die Sicherheitsprüfungen des Clients, in dem das
ZETA-SDK eingesetzt wird.

Die Anforderungen wurden nach den MASVS-Kategorien klassifiziert.

Hinweise:
- In manchen Kommentaren wird von "Anwendung" und dann wieder von "Client"
gesprochen. Diese Begriffe werden hier austauschbar verwendet.
- Das SDK speichert keine fachlichen Daten. Diese werden nur durchgeleitet vom
Fachclient an den Fachdienst (via ZETA Guard) und andersherum.
- Das SDK speichert und nutzt Anmeldedaten (wie Client Instancey Keys, Access-, Refresh-Token und DPoP-Keys), die auch sensitive klassifiziert sind.
Die Speicherung dieser Daten wird an den umliegenden Client delegiert und überträgt
damit die Verantwortung für die Umsetzung der TRs auf den Client-Hersteller.
- In mobilen Anwendungen wird für die Verwaltung des Client Instance Keys die
hardwaregeschützte Schlüsselverwaltung des Systems verwendet.

## Storage

Die API des ZETA-SDK erwartet, dass der Client dem SDK eine Funktion zur
sicheren Ablage sensibler Daten wie Access-Token bereitstellt — im besten Fall
eine, die es bereits gibt. So wird geprüfte Funktionalität wiederverwendet und
Doppelimplementierung vermieden. Damit richten sich die Anforderungen im Bereich
Storage aber an den Client-Hersteller.

Die folgenden Anforderungen stammen im Wesentlichen aus der BSI TR-03161-1, decken aber auch die
MASVS Anforderungen ab, die vom Client umzusetzen sind:

- MASVS-STORAGE-1 The app securely stores sensitive data.
- MASVS-STORAGE-2 The app prevents leakage of sensitive data

## Crypto

Die MASVS definieren:

- MASVS-CRYPTO-2 The app performs key management according to industry best practices.

Die TR-03161-1-Anforderungen sind in diesem Fall eine Konkretisierung der MASVS und greifen hier, weil die Schlüssel derzeit nicht im
TPM liegen, sondern im delegierten Storage. Ausgenommen ist der
Client-Instanzschlüssel auf Android- und iOS-Geräten mit hardwaregestütztem
Schlüsselspeicher.
